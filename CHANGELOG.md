# Changelog

All notable changes to florn are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions follow semantic versioning; tags carry no `v` prefix.

### Added
- RFC 008, the network domain, accepted on 2026-10-24; its Phase 2 handoff package under `rfcs/handoffs/008-network-domain/` (PR-15 to PR-22, release 0.2.0).
- The domain interface (RFC 008 §2, PR-15): the `Domain` trait of `florn-host` with a composed world dispatching by port type, domain events, scheduled changes and interventions of a domain's kinds routed to the domain, built-in actors run by their domain with `metered = 0`, a domain's imports answered inside an activation, its units in the config, its state in checkpoints. `Run` and `Controller` take the Host's `Domains`. - The contract of record `contracts/florn-network/wit/network.wit` (`florn:network@0.1.0`) with its equality test, and the SDK crate `florn-guest-network`: the router world's bindings, the `Router` trait, `link_info`, `router!`; the example guest `net_echo`, the first rung of the ladder.
- The module manifest's domain tables (`[network] protocol = "..."`), carried opaquely to the domain; `Domain::validate_module`.
- Six shipped network scenarios with recorded digests (`net-delay`, `net-loss`, `net-jitter`, `net-link-down`, `net-lan`, `net-blackhole`), run natively and in the three browsers; the RFC 008 §12 tests.
- The display stream and its transport (RFC 005 rule 14, PR-18): sixteen-byte records in `florn-control` (`display`: `instant`, `flight`, `activity`, with the encoding and the reduction above the transport), written by the Host per Host tick under the new `display` subscription and never otherwise; the browser page's one reader over two implementations, the ring in shared memory where the page is cross-origin isolated and one transferred message per Host tick otherwise, in `crates/florn-ui-web/www/display.js`; the run's log opens with `telemetry.transport`, and what either path drops is `telemetry.dropped` with the path and the count. The conformance kit's native tests of the stream and its browser run over both paths: identical records, the cell at 2,000 records per frame, the drops of a stalled page.
- The browser application (RFC 005 rules 38 to 41, PR-20): the Leptos shell on the main thread, in English and Japanese, with the run controls, the learning labs, the actors list as the canvas's twin, the topology on a canvas, the inspectors, the timeline with filters, the interventions and the ended run's kept ones, authoring with validation at the field, files in and out (scenario, run record, module), the status line with the instant, the transport, dropped records and the measured draw time, and the offline signal of the service worker. Its catalogues: the labels checked at compile time, the codes' sentences checked by a test. The loader `www/app.js` and the page `www/index.html`; the kit's page is `www/kit.html`. The journeys J1 to J4 as Playwright scripts in Chromium, Firefox and WebKit in CI, with the language switch mid-run, the keyboard bound, the offline start, the frame figure and the one-origin network log; `ci/build-shell.sh` builds the application and `ci/check-shell-exports.sh` holds the loader to the control interface.
- The view model and the scene (RFC 005 rule 37, PR-19): `florn-ui-model` (the topology with link state, flights and activity; the timeline from the trace and the notifications with filters; the inspectors of an actor, a connection, a message and the world; the interventions asked and applied, and the ended run's kept; authoring as a draft with validation at the field; the outbox a shell sends) and `florn-ui-scene` (the layout, the items to draw with status by shape, the flights moving without an update per event, hit testing, the canvas's description), both native and tested over the real Host through the journeys' data flow (J1 to J3 and the authoring of J2). The control interface's 0.2 additions they read: the `decode` and `payload` queries; a connection's type and attributes, an actor's configuration, a module's channel layouts and domain tables, the scheduled changes, the event classes in the `scenario` answer; a handled event's sends by digest in the trace window.
- The ladder's second rung (RFC 008 rule 20, PR-17): the `distance_vector` example of `florn-guest-network`, with periodic and triggered advertisements, split horizon, count to infinity, expiry after three periods, the metric from `link-info`, and the `neighbour` and `route` reports; its decoder in the network domain; the shipped scenarios `dv-triangle` and `dv-chain` with recorded digests; the convergence, reconvergence, J3 replay, infinity, expiry and decoder tests.

### Changed
- The dependency gate weighs the features florn builds (the shell's included) rather than every feature of every crate; the Boost licence is allowed as permissive; two "unmaintained" notices on build-time dependencies of the shell's framework are listed with their reasons (RFC 006 amended).
- Loading a scenario after a run ended gives the engine back to the Host, so that the next run or replay starts instead of being refused as not now.
- A paced slice (`pump`) advances from the tick reached rather than from the last event handled, so that a scenario with sparse events progresses slice by slice. An admitted module from a file is named by its kind until a scenario names it.
- A replay stores the chain at every point its record holds and compares there, so that a record exported before its run ended replays to a match instead of a false divergence.
- The browser worker is a module script and takes the display transport at `florn_start`; the test page reads the display stream with `?display=1`. The browser CI serves a second origin without the isolation headers for the message path.
- The engine adapter trait: an import carries its interface's module; an export is resolved with its flat shape. The browser worker binds a guest's imports from a binding text the adapter writes.
- Admission reports a module manifest's own refusals beside stage 1's when the manifest cannot be read, instead of hiding them behind `module.import-refused`.
- The thirteen public crates (the runner `florn`, the SDK `florn-guest`, and their library chain) are published on crates.io at 0.1.0 from the 0.1.0 release's code; the documentation names `cargo install florn` and `florn-guest = "0.1.0"` first.

## [0.1.0] - 2026-10-20

The first release: the core on two Hosts (Phase 1 of the roadmap). The release notes with the figures, the security review and the file hashes are `docs/src/releases/0.1.0.md` and the GitHub release.

- RFC 001, the determinism contract. Accepted 2026-10-13.
- RFC 004, the core model: graph, scenario manifest, package. Accepted 2026-10-13.
- RFC 002, the guest contract: artifact, ABI, activation, layering. Accepted 2026-10-14.
- RFC 003, module admission and resource limits, with the versioned cost model and the metering-cost plan. Accepted 2026-10-14.
- RFC 005, the Host architecture: one core, adapters, control interface, repository layout. Accepted 2026-10-14; amended the same day with the telemetry-transport and snapshot-and-restore results.
- RFC 006, the security baseline for the browser Host. Accepted 2026-10-14. Copyleft licences refused outright.
- RFC 007, the error model and internationalisation. Accepted 2026-10-14.
- Requirements specification, revision 3, under `docs/`. Accepted 2026-10-13.
- External design, revision 2, under `docs/`. Accepted 2026-10-14.
- Roadmap. Authorised 2026-10-13; Stage 0 results recorded through 2026-10-14.
- Repository skeleton: licence, notice, readme, this changelog.
- Phase 1, PR-01: the Cargo workspace of RFC 005 with eighteen empty crates, the pinned toolchain, the contract of record `contracts/florn-core/wit/core.wit` with the test that keeps it equal to RFC 002, and the dependency-direction check in CI.
- Phase 1, PR-02: `florn-model`, the core model of RFC 004: manifest parsing with every validation code reported in one pass with typed parameters, quantities converted exactly to ticks and bytes, the canonical encoding and the scenario hash, the package reader and writer. RFC 007 section 4.1 gains four codes.
- Phase 1, PR-03: `florn-kernel`, the logical world of RFC 001: ticks and instants, the event key with both tie policies, the zero-delay limits, seeded streams over an in-crate ChaCha8 derived with BLAKE3, activations that commit in order or discard everything, timers with replace and cancel, interventions as recorded and replayed inputs, trace records with payload digests, the BLAKE3 chain, run comparison, and the advance units.
- Phase 1, PR-04: `florn-abi`, the canonical ABI lifting and lowering of the type subset of RFC 002, shared by both engine adapters: layout and flat representation, the sixteen-flat spill, strict lifting that produces the contract fault, canonical NaN, and the core world's signatures checked against the contract of record.
- Phase 1, PR-05: `florn-engine`, the engine adapter trait of RFC 005: compile with a cache by bytes, instantiate with the world's imports and the Host-owned globals, typed cached calls with an import handler, memory views, globals and tables for state export, trap kinds; and the adapter conformance cases over a hand-written guest of the core world. `florn-engine-wasmtime`, the Wasmtime adapter with the deterministic settings, store limits, and the epoch as the Host's watchdog. Wasmtime is pinned at 48.0.6, the patch of the long-term-support line that closes its advisories.
- Phase 1, PR-06: `florn-admission`, the admission step of RFC 003: validation with the exact feature set and a code for every refusal; both custom sections, the contract identity decoded by its interfaces, the manifest schema of RFC 002; the estimate of needs against limits and of instances and memory against capacity before anything exists; the transformation in its fixed order, with custom sections and exported global indices corrected around the library; the state layout; the admission cache; the config encoder. The admitted hash of the kit guest is recorded for admission version 1. RFC 007 section 4.2 gains two codes; RFC 003 rule 9 records the library behaviours the wrapper corrects. `zip` moved to 9.0.4 for the advisories of the 8 line.
- Phase 1, PR-07: `florn-host`, the Host core over the engine and platform traits: the run loop of RFC 005 rule 15; activations with the budget in place before lowering, fault classification by globals, the quotas in the import handlers; the instance pool with the estimate before anything exists; actor export and restore and checkpoints with one canonical encoding; the diagnostic log; the run identity and run inputs; the run record (`.florn-run`) written and read; replay with the recorded interventions and the comparison at every stored point. With it: the notification types of RFC 007 rule 3 in `florn-control`, the platform trait with the probe, the seed and the wall clock in `florn-platform`, kernel and trace snapshots, and the engine's name and version for the identity. AC-002, AC-003, AC-004 and AC-006 pass natively with hand-written guests. RFC 007 gains `run.limit-exceeded`; a duplicate `module.contract-mismatch` row that PR-06 had added is removed (the code carries the module's name, as section 4.1 says).
- Phase 1, PR-08: `florn-control`, the control interface of RFC 005 section 6: the commands, queries, subscriptions, answers, telemetry and progress messages of rule 26 as Rust types with one canonical encoding and the interface version; the catalogue of every code of RFC 007 section 4 with typed parameters, kept equal to the RFC's tables by a test, and the check of a notification against it; the structural validation of a command. In `florn-host`, the controller every front end drives: it validates every command before it acts, refuses with `control.invalid`, `control.not-now` or `control.version`, paces an advance in slices the front end asks for, previews every export, and replays a record. RFC 005 rule 26 gains `load-module`.
- Phase 1, PR-09: `florn`, the headless runner of RFC 005 rule 31: `run` prints the chain and writes the run record, `replay` prints the comparison, `admit` prints the manifest and the admitted hash, `probe` prints the capacity; a front end like the others, driving the Host through the control interface. `florn-platform-native`: the wall clock, entropy for the seed of a new run, and a provisional capacity until the probe is measured. The runner's English table: one sentence per code of RFC 007 section 4, the English source of rule 17, kept equal to the catalogue by a test. The Host's hand-written test guests move behind a feature so that the runner's and the kit's tests share them.
- Phase 1, PR-10: `florn-guest`, the guest SDK of RFC 002 section 8: the bindings generated from the contract of record; one declaration that writes the `florn.manifest` section and the config decoder, so that the two cannot disagree; the distributions of RFC 001 rule 30 by algorithms fixed in the SDK; encoders for declared telemetry channels; `now()`; the `std` and `no_std` profiles with an allocator and a panic handler that traps; a template in the crate's readme. The example guests: the echo guest, the NaN probe, and the hostile guests of RFC 003 section 10 (loop, recurse, grow, flood, bad pointer, a WASI import). CI builds them for `wasm32-unknown-unknown`, and a test builds them with the Rust toolchain alone and runs them through the runner: the echo guest admits, runs, and replays to a match; each hostile guest faults with its kind while the neighbour continues; the WASI importer is refused at admission.
- Phase 1, PR-11: `florn-conformance`, the conformance kit of AUTO-007 under the native Host: the SDK's guests built with the toolchain alone (seven new example guests: the pinger, the timers, chatter, heap and clock guests, and the benchmark guests B1 and B2); `scenarios/` at the workspace root with fifteen scenarios and their recorded digests, module hashes and admitted hashes in `scenarios/digests.toml`, compared by the kit's test and so by CI on three architectures; the acceptance criteria AC-001 to AC-006 as named tests and the rows of RFC 001 section 14, RFC 002 section 10, RFC 003 section 10 and RFC 005 section 11 that apply in 0.1, mapped row by row in the crate's readme; the crossing benchmark of RFC 005 rule 11 and the cost benchmark of RFC 003 section 7, whose figures `florn-conformance figures` prints and CI runs on every architecture. The crossing benchmark found the 64 KiB crossing fifty times above the Stage 0 baseline because `florn-abi` lifted and lowered a byte list one value per byte; the ABI now carries a byte list as bytes and the crossing is under the baseline. The Host writes a guest's channel 0 text to the diagnostic log as `actor.text` (RFC 007 section 4.3 gains the code). The guests are shipped as built modules under `scenarios/modules`, because the same source built with the same toolchain gives other bytes on an AArch64 host than on x86-64 (every module; the runs over either build give the same digests); the figures report each machine's own build against the shipped one. The AArch64 runs answer RFC 003's open question 4: the default NaN of `0/0` and `inf - inf` is positive there and negative on x86-64.
- Phase 1, PR-12: the browser Host. `florn-engine-web`: the adapter of RFC 005 rules 6 to 8 and 10, with the Host's WebAssembly calling a guest through its own exported function table and a guest calling the Host through the Host's exports, the budget global shared by every guest and reached through a six-instruction budget module, memory crossed as one copy through views the worker keeps, every instantiation failure a status and a text. `florn-platform-web`: the worker's clock, entropy and capacity. `florn-ui-web`: the Host as a worker module with a C surface (no `wasm-bindgen`), a test page that runs a shipped scenario or a benchmark, and a service worker that starts the page offline with the headers of rule 33. `ci/browser`: a server with the headers and a Playwright driver that runs every shipped scenario in Chromium, Firefox and WebKit against the recorded digests and admitted hashes, checks the hostile faults, the isolation, the policy, the network log, the offline start and the transport's refusal, and prints the crossing and cost figures; CI runs it on Linux and macOS. The engine trait gains a resource failure, which the Host reports as `host.instance-failed`; the benchmark drivers move into `florn-engine` so both Hosts run one measurement; the compute benchmark scenario gets the budget its activation needs.
- Phase 1, PR-13: figures and formats fixed. The conformance kit measures the cost-model units of the reference activations, the hash functions, what the guests need in stack and memory, and the capacity of each Host; RFC 003 rule 19 carries the measured defaults and maxima (the budget default rises from 10,000,000 to 100,000,000 units, since the compute-style reference activation needs 10,150,000), rule 20 the measured instance ceilings (123 in Chromium, 998 in Firefox, none below 5,000 in WebKit, 20,000 natively at the probe's bound), RFC 005 rule 22 the hash figures that confirm BLAKE3 (2.5 to 15 times faster than SHA-256 in the browsers), rule 23 the chain interval of 1,000 records, and RFC 006 section 7 the exact input maxima. The formats of 0.1 are frozen: the trace records, the control messages, `run.toml` and the checkpoint have their encodings recorded by the kit's format tests. The test page gains the hash benchmark and the capacity probe. Wasmtime 48.0.7 closes the advisories RUSTSEC-2026-0378 and RUSTSEC-2026-0379.
- Phase 1, PR-14a: hardening before the release, from the audit of 2026-10-20. The binary `florn` is the `florn` crate's (the runner stays a library in `florn-cli`); a run that ends with a run fault exits with 3; `florn help`. The record and package readers never allocate for a declared size before the bytes arrive, bound the decompressed total, and refuse duplicate entries; a checkpoint's memory is checked against the actor's limit; a module is bounded at load; a record is not exported while a paced advance runs; `admit` uses the loaded scenario's class; the Host reports dropped telemetry and an over-large record with their codes. A failed start hands the engine back, so the browser Host survives an instance failure, which it reports as `host.instance-failed`; the browser worker exports and replays a record. New tests: a divergent replay names its interval natively, through the runner (exit 2) and in the browser; the events-per-instant limit; the capacity warning; an unknown code's rendering; an instance failure in Chromium and Firefox. Continuous integration runs rustfmt and clippy on both targets, quick figures on a push and the full figures on a dispatch or a tag, caches the browsers, and has a weekly fuzz job over eight targets under `fuzz/`. Release artefacts are stripped of symbols; the benchmark drivers sit behind a feature; RFC 002 rule 36, RFC 005 rules 20 and 29, and RFC 006 rule 7 are amended.
