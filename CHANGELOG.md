# Changelog

All notable changes to florn are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions follow semantic versioning; tags carry no `v` prefix.

## [Unreleased]

### Added
- RFC 009 (checkpoints, backward navigation, branching, actor swapping, and the application's depth), RFC 010 (cost model version 2: florn's own metering pass) and RFC 011 (the BGP subset and its learning lab) proposed and accepted on 2026-10-29 for release 0.3.0, Phase 3 of the roadmap; its handoff package under `rfcs/handoffs/009-depth/` (PR-23 to PR-30).
- Cost-model version 2 (RFC 010, PR-24): florn's own metering pass, charging version 1's units at version 1's blocks into a local of the function and touching the budget global only before calls, before a loop's back-edge, before a return and at a function's end; a run without a fault gives the same digest under both versions, and a run under version 1 replays under version 1. The version is a run input and a Host setting (`set-cost-model`, `florn run --cost-model`); the admission refusal `module.segment-too-long`; the kit's figures and `[admitted-2]` hashes under both versions; the fuzz target over both. The default stays version 1 until the figures of every engine are in.
- The application's depth (RFC 009 sections 6 and 7, PR-28): "Go to…" and "Step to here" move back as well, saying first what they would undo, and the undone interventions are listed to re-apply at their instants or to discard; the world inspector lists the kept checkpoints with "Take a checkpoint now", "Export" and "Branch from here", names a branch's parent, and the timeline marks the branch; "Load a checkpoint…" starts a run from a file; the run controls choose between all actors resident and swapping beyond the capacity, and the status line says "swapping" with the counts and "limited by" memory or swapping from the Host's own figures (`host.limited-by`, said from a paced slice that overran its share of the second); origin storage keeps what you open, save, import or export as a cache listed under Files with its size, to reopen or export, an eviction said as a fact (`storage.evicted`); a module imported from a file shows both hashes before it can be placed, and a WebAssembly Component is refused with `module.component`; the application is installable from its own origin (a manifest and two icons, nothing else); the browser Host keeps only the trace records since the last checkpoint and assembles an export's trace by replay; the journeys J5 and P1 to P4, the installable manifest and the address after every journey are checked in three browsers.
- Actor swapping (RFC 009 section 5, PR-27): `new-run { residency: swap }` runs a scenario through a resident set smaller than its actor count, the probed capacity less one, exporting and dropping the least recently activated actor when the pool is full and restoring an actor into a fresh instance from the compiled cache before its activation; the trace and the digest are the resident run's, the conformance kit asserting it with pools of one and two on every shipped scenario up to 20,000 records and on the lab in three browsers; `host.swapping` says the resident count, the actor count and the measured cost per kilobyte; without it a scenario beyond the capacity is refused as before, and one actor beyond the memory is refused even with it; a checkpoint of a swapping run is the resident run's byte for byte and restores in either; the runner's `--residency`, the kit page's `residency` and `resident`.
- Branching (RFC 009 section 4, PR-26): the `branch` command starts a new run from the current instant of the current run, at a boundary, with the parent's inputs up to there as its own; the parent ends and its record, with the trace it kept, is held for `export { kind: parent-record }` until the next run starts; the branch's `run.toml` carries a `[parent]` table (the parent's chain value, record count and instant) and its chain holds the branching point, so that its replay compares there and needs nothing of the parent; a branch begins at its instant and moves back no further; the code `run.branched`; the kit page's `branch-at` and the cross-Host check that both records of a branch made in the browser replay natively.
- Backward navigation and detail by replay (RFC 009 section 3, PR-25): `advance { to }` with an earlier tick restores the nearest kept checkpoint at or before it and executes forward; the interventions after it are undone and said, and a replay re-applies them; the start of a run is a kept checkpoint that no budget drops; `trace-window` answers a window the Host keeps no records of by re-executing from the nearest checkpoint through the run's own instances, with the present checkpointed and restored around it and nothing logged on the way.
- Checkpoints (RFC 009 section 2, PR-23): the Host takes one every 10,000 handled events at the next boundary and on the `checkpoint` command, keeps them under a memory budget by thinning the older ones (the newest eight always), lists them (`checkpoints`), restores one in place (`restore`: the trace after its instant discarded, the interventions after it undone and said with `run.rewound`, re-applied by a replay), exports one as a `.florn-checkpoint` file after the preview, and starts a run from such a file (`load-checkpoint`) with the identity checked field by field; the file is bounded by the maxima of RFC 006 section 7. The runner gains `resume` and `run --checkpoint-at --checkpoint-out`; the kit proves a checkpoint crosses the Hosts both ways in CI. The codes `checkpoint.taken`, `checkpoint.budget`, `run.rewound`.

### Changed
- The service worker's cache is `florn-0.3`; a backward `advance { to }` is accepted from a run that ended, as from a pause; an intervention requested before an instant for an instant after it is undone by a move back to that instant, like one applied after it.
- The Wasmtime adapter gives every instance a store of its own: Wasmtime frees an instance's memory with its store and never before, so one store holding every instance ever made met its limit once a swapping run had made ten thousand; the budget global is one per instance there, set before every activation as it always was. The platform trait gains a monotonic clock in microseconds for the Host's own measurements.
- New runs default to cost-model version 2 on every Host (RFC 010 rule 9, the owner's decision of 2026-10-29 on the figures); version 1 stays for replay and `--cost-model 1`. The shipped `[admitted]` hashes are version 2's; the recorded digests of the hostile scenarios whose fault is a stack fault or a trap changed with the version (a trap is metered without the local's remainder), every other digest stands.
- The checkpoint encoding is version 2: it carries the composed world's sequence counters per domain origin, without which a restored run ordered equal-time events otherwise. Version 1 was never written to a file.

### Fixed
- The browser worker's engine glue read every pointer and length the Host passed as a signed 32-bit value and kept a dropped instance's exports in its function table: a Host memory beyond 2 GiB (the exported state of a thousand swapped actors) broke the reads, and a dropped instance never gave its memory back. Both are fixed. An actor's state in memory, in checkpoints and as swapped state, holds the 4 KiB chunks of its memory that have a non-zero byte, the file form unchanged: a guest's memory is mostly zeros, and the start checkpoint of 1,500 swapped actors held 1.6 GiB otherwise. A panic in the browser Host is logged with its text instead of a bare trap.
- A replay's comparison read through the Host's API (`Run::comparison`) wanted the record to hold as many chain points as the replay stored, so a record exported before its run ended compared as incomparable there while `replay.matched` said otherwise; it compares at every point the record holds, as the notification does (RFC 001 rule 50).
- The several deliveries of one send (a lan's frame reaching every other port) shared one event key and the queue's own order decided between them, so that stepping one event at a time, or restoring a checkpoint, gave another digest than running through. Equal keys are ordered by the target's identity (RFC 001 rule 17 amended); the shipped `net-lan` digest, recorded from a run straight through, stands.

### Changed
- The dependency gate weighs the features florn builds (the shell's included) rather than every feature of every crate; the Boost licence is allowed as permissive; two "unmaintained" notices on build-time dependencies of the shell's framework are listed with their reasons (RFC 006 amended).
- Loading a scenario after a run ended gives the engine back to the Host, so that the next run or replay starts instead of being refused as not now.
- A paced slice (`pump`) advances from the tick reached rather than from the last event handled, so that a scenario with sparse events progresses slice by slice. An admitted module from a file is named by its kind until a scenario names it.
- A replay stores the chain at every point its record holds and compares there, so that a record exported before its run ended replays to a match instead of a false divergence.
- The browser worker is a module script and takes the display transport at `florn_start`; the test page reads the display stream with `?display=1`. The browser CI serves a second origin without the isolation headers for the message path.
- The engine adapter trait: an import carries its interface's module; an export is resolved with its flat shape. The browser worker binds a guest's imports from a binding text the adapter writes.
- Admission reports a module manifest's own refusals beside stage 1's when the manifest cannot be read, instead of hiding them behind `module.import-refused`.
- The thirteen public crates (the runner `florn`, the SDK `florn-guest`, and their library chain) are published on crates.io at 0.1.0 from the 0.1.0 release's code; the documentation names `cargo install florn` and `florn-guest = "0.1.0"` first.
