# florn 0.2.0

2026-10-29. The second release: the network learning lab. Phase 2 of the roadmap.

## What it is

On the core of 0.1.0, unchanged in meaning:

- The domain interface: a domain is a crate of the Host core behind one trait, with its connection and port types, its validation and units, its event classes, the world its guests need beyond the core, its delivery rule, its scheduled changes and intervention kinds, its built-ins and its decoders. The kernel knows no domain (RFC 008 section 2).
- The network domain: `network/link` and `network/lan` over `network/interface` ports; delay, bandwidth, jitter, loss, mtu, enabled, and the per-port cost and mtu; frames delivered after delay and serialisation, jitter and loss drawn from the connection's own streams; the `link` and `node` interventions; the `network/blackhole` built-in; decoders for the ladder's protocols (RFC 008 sections 3 to 9).
- The router contract `florn:network@0.1.0` and the SDK crate `florn-guest-network`: the core world plus `link-info` and `on-link`, `Router` and `router!`.
- The ladder of guests: `net_echo`, `distance_vector` (periodic and triggered advertisements, split horizon, count to infinity, expiry) and `ospf`, a declared subset of OSPF (one area, hello and dead intervals, point-to-point adjacencies, router-LSAs flooded with sequence numbers and acknowledgements, Dijkstra) that refuses what lies outside it with a logged reason (RFC 008 rules 20 and 21).
- The display stream and its transport: sixteen-byte records written by the Host per tick, over a ring in shared memory where the page is isolated and over messages otherwise (RFC 005 rule 14).
- The view model and the scene, native and framework-free: what is shown and what is drawn, over the control interface alone (RFC 005 rule 37).
- The browser application: the shell on the main thread, in English and Japanese; run controls and pacing; the learning labs with their stories; the actors list as the canvas's twin; the topology with frames in flight; the inspectors of an actor, a connection, a message and the world; the timeline with filters; interventions that say when they applied; authoring with validation at the field; save, load, import, export after a preview, replay; the states; offline after one visit (RFC 005 rules 32 to 41).
- The learning lab `ospf-lab` and nine other bundled network scenarios, each with a recorded digest; the journeys J1 to J4 of the acceptance criteria as Playwright scripts in Chromium, Firefox and WebKit.
- The control interface's additions within version 1: the `decode` and `payload` queries, the `display` subscription, the summaries' domain fields, `intervention-content`.

Not in this release: checkpoints and backward navigation, origin storage for modules, a second protocol family, the native shell. Release 0.3.0 is depth: checkpoints, branching, BGP, the metering pass.

## Getting it

| Asset | What |
|---|---|
| `florn-0.2.0-x86_64-unknown-linux-gnu`, `florn-0.2.0-aarch64-unknown-linux-gnu`, `florn-0.2.0-aarch64-apple-darwin` | The runner |
| `florn-app-0.2.0.tar.gz` | The browser application: the shell, the Host's worker module, the kit's page and the shipped scenarios, to serve under the headers of RFC 005 rule 33 at an immutable versioned path |
| `SHA256SUMS` | The SHA-256 of every asset and of every file inside the application bundle; the release body repeats it (RFC 006 rule 5, step 7) |

From crates.io: `cargo install florn`; a guest depends on `florn-guest = "0.2.0"` and, for the router world, `florn-guest-network = "0.2.0"`. The fifteen public crates (the runner, the two SDKs, the network domain and their library chain) are published at 0.2.0. From source: `cargo install --path crates/florn` from a checkout of the tag, or `cargo install --git https://github.com/nabbisen/florn --tag 0.2.0 florn`; the application is built from a checkout with `ci/build-shell.sh`.

## What was checked

Continuous integration on the release commit: rustfmt and clippy on both targets, the shell included; the whole test suite on x86-64 Linux, AArch64 Linux and Apple Silicon; the conformance kit's scenarios in Chromium and Firefox on Linux and WebKit on macOS against the digests recorded natively; the journeys J1 to J4 in the three browsers, with the language switch, the keyboard bound, the offline start, the frame figure and the one-origin network log; the catalogues in both languages with every key present; the shell's exports; the licence and advisory gate over the features florn builds; the dependency direction; the RFC index; the book; the eight fuzz targets for three minutes each on the dispatched run named below. The acceptance criteria AC-008 to AC-013 are the journeys; the owner's own checks of the acceptance checklist run at the owner's pace.

The shipped modules were rebuilt for this release because the SDK writes its version into every module manifest: the modules' hashes changed, the trace digests did not.

## Compatibility with 0.1.0

- A guest written for 0.1.0 builds unchanged against `florn-guest` 0.2.0; `declare!` gains the optional `tables` entry. A module built with the 0.1.0 SDK is admitted by a 0.2.0 Host.
- Scenarios, packages and run records of 0.1.0 are read by 0.2.0 unchanged; a 0.1.0 run record replays under 0.2.0 when its modules are supplied.
- The control interface stays at version 1 with additions; a 0.1.0 Host refuses the additions as unknown, and the 0.2.0 application reads a 0.1.0 Host's answers.
- The shipped scenarios' digests are unchanged; the modules' hashes changed, as said above.

## Known limitations

- The browser Host assumes its instance ceiling by family (120 in Chromium-based browsers, 990 elsewhere) rather than probing at start-up, since a probe uses up what it measures.
- WebKit's worker timers fire about every 20 ms, so a slow pace in WebKit is coarser than the chosen one; the run's logical time is unaffected.
- The application replays a run record; it does not play back a trace, and it has no checkpoints to move backward from. Both are 0.3.0.
- The OSPF guest is a declared subset: one area, point-to-point adjacencies, router-LSAs. Several areas, designated routers, network-LSAs and summaries are outside it and refused with a logged reason.
