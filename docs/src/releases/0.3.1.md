# florn 0.3.1

2026-11-03. A patch release of 0.3.0. It corrects a parser that a hostile scenario could make allocate without bound, makes the project's gates able to fail, and repairs a few small defects found on the way. It adds no feature and changes no recorded digest.

## What it is, and why

A patch release is made only for a defect that accepts hostile input unsafely, gives a wrong result, or loses data (the roadmap's rule). Each item below is one of those, or the gate that failed to see one.

**The parser.** A scenario could make the runner ask for a text of a size the scenario chose. `end = "1e2000000000s"` made it build the number's plain text, two gigabytes, and abort; a `real` parameter in an actor's `config`, a limit or a duration in a domain's attribute did the same. A quantity's exponent, once normalised, is now at most 1000 in magnitude, which is past the range of a 64-bit float; a larger one is `quantity.out-of-range` naming the field, with the value as written cut to 64 characters. The same bound holds for the text a number is written back as. The runner refuses the scenario above under a 1 GB memory limit, as a regression test.

**What a quantity too large is called.** A number of more than 39 digits, or a duration or a size that is whole but beyond what 128 bits hold once converted (`1e30s` at a tick of 1 fs, `1e50B`), is `quantity.out-of-range`. It was `manifest.type`, or `quantity.not-whole-ticks` with a smallest tick the code made up. A `ticks`, `integer` or `real` parameter in an actor's `config` beyond the bounds is `quantity.out-of-range` naming the parameter, and not `config.type`.

**Zero.** A duration of zero was refused as not a whole number of ticks (`end = "0ns"` named "the smallest tick that fits is 1fs"), because the normalised zero was read as digits below the unit. Zero is whole in every tick length. It mattered beyond `end`: the BGP guest declares `keepalive` with the default `0s`, meaning a third of `hold`, so a router that left `keepalive` out could not be loaded. A run with `end = 0` ends at once with `end-reached`, holding only the actors' `init` activations at tick 0.

**The gates.** `ci/fuzz.sh` always exited 0, because it piped each run into `tail`, and it read a failing `cargo fuzz list` as no targets; it now fails when a target crashes, when the list fails and when it is empty, the fuzz job uploads the crash inputs and keeps its corpus between runs, and every target runs under an RSS limit of 1024 MB, set from a measurement (the largest peak of the eight targets over 60 seconds each was 645 MB), because libFuzzer's default of 2048 MB does not see an allocation of 1.9 GB, and the manifest target starts from the shipped scenarios. The limit and the seeds make a find likelier; they do not promise one in a given run. `ci/check-rfc-index.sh` did not fail for an indexed file that is missing. New: `ci/check-rfc-invariants.sh` (an RFC's status line names its folder's state; relative links resolve), `ci/check-private-paths.sh`, and `ci/test-gates.sh`, which plants one violation at a time in a scratch copy and checks that each control rejects it (21 controls). The browser kit retries a navigation once in a fresh context after a timeout or a crashed page and prints the count; the key sets of the two languages' labels are compared by a test.

**Hostile input in hexadecimal text.** A module's `sha256`, a run record's and a `run.toml`'s hexadecimal fields, a world content's payload and a payload digest in a query were read by slicing the text two bytes at a time after counting its bytes. A text of the right length that held a multi-byte character was split in the middle, and the Host panicked: on a scenario, a run record or a checkpoint file chosen by whoever wrote it. They are read by bytes and by digits now, and a text that is no hexadecimal is refused with its code. One behaviour changes: a digest with a leading `+` was read as valid and is refused. The parser's fuzz target did not find it for as long as it ran from nothing; started from the shipped scenarios, it did in minutes.

**Smaller things.**

- The network domain warned `network.telemetry-layout` for the BGP guest's `route` channel; RFC 008 lists two layouts of `route` and the check knew one. Both are read, and the BGP lab starts with nothing in its log but information.
- `florn resume --to TICK` exited 0 when the run met a run fault on the way to the tick. The exit code follows the end reason whether or not `--to` is given: 3 for a run fault (`ended = host-fault`).
- The authoring draft cannot take a built-in actor (the control interface's summary carries no built-in's name), so the draft of a scenario with one wrote a manifest that did not load. See the limitation below.

## A limitation

A scenario with a built-in actor (the shipped `net-blackhole` has one) cannot be taken whole into the editor. The editor says which actors it could not take, and it neither applies nor saves such a draft; the scenario that is loaded still runs as it was, and a new scenario can be authored as before. Keeping the built-in itself needs its name on the control interface, and that comes with 0.4.0.

## Public additions

0.3.1 adds, to published crates, and removes nothing:

- `florn_model::Quantity::classify` and `florn_model::QuantityRefusal`: `Quantity::parse` with the reason it refuses. They are public for the workspace's crates and hidden from the documentation (`#[doc(hidden)]`); they are not part of the stable API and may change in a release that is not a patch release. `QuantityError` is unchanged.
- `florn_ui_model::Draft::dropped` and `Draft::can_apply`: the actors a draft could not take and whether it may be applied or saved. The shell reads them; they are the application's contract with its shell.

`Quantity::to_ticks` and `Quantity::to_bytes` return `Ok(None)` for a value too large, as they did for one beyond 64 bits, where they returned "not whole" before; `Decimal::as_integer_at` returns `Some(0)` for zero at every scale. Their signatures are those of 0.3.0.

## Not in this release

The circuit and control domain (release 0.4.0), the native shell, and everything else the roadmap places after 0.3.0.

## What was checked

- **Digests.** All 27 recorded digests reproduce, natively and in Chromium, Firefox and WebKit through the kit; `scenarios/` is untouched.
- **Tests.** The whole suite on x86-64 Linux, AArch64 Linux and Apple Silicon, with the new ones: the exponent and the 39 digits at their edges, each code a value too large or too small now has, zero in every tick length, a hostile `end` under a 1 GB memory limit through the real runner, a `hold` of an enormous number through a real guest, the BGP lab's log, the exit code of a run stopped by `--to`, the draft that is not applied, hexadecimal text of every shape that is not hexadecimal. Each was shown to fail on the code before the change.
- **The browser.** The kit (272 checks) and the journeys (174) in Chromium and Firefox, and WebKit on the macOS runner; the journeys now include the refusal of a draft that dropped an actor, in both languages.
- **The security review of the parser change** (RFC 006 rule 5, step 2; recorded in the review of the unit). Every place where a number the scenario wrote could set a size or a count was followed: the decimal's parse and its text, the conversion to ticks and bytes, the configuration encoder, the messages that carry a value, the domain's use of a decimal. Each is bounded by a constant (the exponent bound, 39 digits, 64 characters) or by the size of the input itself; none by the value of a number. No data flow, integration or capability is added, so the threat model is unchanged.
- **The fuzz job.** The eight targets, 180 seconds each, in a dispatched run on the release commit: RUN_PENDING. How the gate was shown to work: on the parser as it was before the exponent was bounded, the manifest target under the new limit found nothing in 3.6 million runs from nothing; started from the shipped scenarios it found the hexadecimal panic above, and with that fixed it found the allocation of two gigabytes in one of two runs of 180 seconds. The job makes a find likelier; it does not promise one in a given run.
- **Licences and advisories.** `cargo deny check licenses advisories bans sources` passes; no dependency is added or changed.

The owner's checks C23 to C29 of the 0.3.0 handoff run at the owner's pace; this release does not wait for them.
