# 学習ラボ

ラボは同梱シナリオ `ospf-lab` です。RFC 008 規則 21 の OSPF サブセットを動かす 4 台のルーターが、弦をもつリングを作り、実行の途中でひとつのリンクが切れて、また直ります。アプリケーションの「学習ラボ」の先頭にあり、受け入れ基準のジャーニーがすべてのブラウザーで動かすシナリオでもあります。この章はそのラボを順に歩き、最後に他の同梱シナリオに触れます。

## はじめる前に

アプリケーションを開き（起動やビルドの方法は[インターフェースの章](./interface.md)にあります）、「学習ラボ」から「OSPF：弦のあるリング」を選びます。トポロジーには r1 から r4 がリング状に並び、r1-r2、r2-r3、r3-r4、r4-r1 の接続と、五つめの接続である弦 r1-r3 が見えます。弦のポートはコスト 5 で、他のポートはすべてコスト 1 です。キャンバスの横のアクター一覧はキャンバスの双子です。各ルーターは Tab で止まる位置で、Enter で選択すると、キャンバスのクリックと同じことが起きます。

まだ何も実行されていません。最初は速度を遅く、毎秒 100 ティックにしてください。フレームが飛行中に描かれます。ラボ本来の速さ、毎秒 1,000 ティック以上はあとで使います。

## 見えるもの

**hello と隣接、ティック 0 から 200。** 各ルーターは 50 ティックごとに、それぞれのインターフェースで hello を送ります。パケットにはルーター ID、間隔、そのインターフェースで聞いた ID が入っています。隣のルーターの hello に自分の ID が入っているのを聞いたルーターは、隣接を full と宣言します。r1 を選んでインスペクターを見てください。最新のテレメトリにはポートごとの `neighbour` 報告があり、それぞれが hello 2 周期以内に down から full になります。タイムラインにはアクティベーションが起きるたびに並びます。アクターで絞り込めば 1 台を追えます。

**フラッディング、ティック 100 から 400。** 隣接が full になったルーターは、新しい隣に自分のリンク状態データベース全体を送り、自分のルーター LSA、つまり隣接とそのコストの一覧を、シーケンス番号つきで生成します。各ルーターは受け取ったものを他の full な隣接へ流し、確認応答を返します。タイムラインで `update` パケットの送信がフラッディングです。行を開くとメッセージインスペクターがデコードします。型、送信者、エリア、そして LSA ごとに `origin#sequence[neighbour:cost, ...]` です。

**収束、ティック 400 から。** すべての LSA がすべてのデータベースに揃うと、各ルーターはグラフの上で Dijkstra を走らせ、宛先ごとに `route` を報告します。次ホップのポートとコストです。r1 のインスペクターでは、r3 へはコスト 5 の弦ではなく、r2 か r4 を通る近い側のコスト 2 で届きます。インスペクターは報告された経路を示します。変わった経路は新しい次ホップで再び報告され、消えた経路は取り消されます。

**切断、ティック 1,500。** シナリオは r2-r3 のリンクを 1,500 で無効にするよう予定しています。接続は破線で描かれます。飛行中だったフレームは届き、その時点以降の送信は落とされます。ルーターは dead 間隔で気づきます。hello のない 200 ティックで隣接が down になります。r2 と r3 はどちらも隣接を取り消し、より大きなシーケンス番号で自分の LSA を生成し直し、フラッディングが変化をリングに運びます。向こう側への経路が動きます。r2 は r3 へ反対回り、r1 と r4 を通ってコスト 3 で届きます。弦ならコスト 6 です。dead 間隔が終わって hello 2 周期以内に、r2 のインスペクターの `route` 報告が変わるのを見てください。

**修復、ティック 3,000。** リンクが再び有効になります。hello が渡り、隣接はまた full になり、LSA が生成し直され、経路は最初の値に戻ります。実行は 4,500 で終わります。

## 試してみること

- **別のリンクを切る。** キャンバスかタイムラインで接続 r3-r4 を選び、インスペクターの「次の時点でこのリンクをダウンさせる」を使います。介入は「介入」に、適用された時点とともに並び、r4 は r1 を通って他のルーターに届くようになります。同じやり方で戻せます。
- **ルーターを落とす。** r2 を選んでダウンさせます。隣の dead 間隔が切れ、隣は LSA を生成し直し、r2 の LSA は他のすべてのルーターの経路から消えます。宛先がインスペクターから消えます。
- **切断をステップで追う。** 1,500 の前で一時停止し、ステップ単位をイベント 1 つにして、ステップします。アクティベーションごとにタイムラインの 1 行とキャンバスの 1 つの変化です。
- **再実行する。** 実行が終わったら実行記録ファイルをエクスポートします。プレビューがファイルの中身を言います。入力、介入、トレースで、ペイロードは残すと選んだときだけです。それを再実行すると、アプリケーションは入力からシナリオをやり直し、あなたの介入をその時点で適用して、ダイジェストが一致したかを報告します。一致します。
- **保存して開き直す。** シナリオを保存し、開き直すと、予定、属性、コストは置いたままです。終了した実行の介入は、予定された変更として残せます。

同じシナリオはコマンドラインでも動きます。シードは `scenarios/digests.toml` にキットが記録したものです。

```sh
florn run scenarios/ospf-lab.toml --modules scenarios/modules --seed 1
```

`chain` の行が実行のダイジェストで、アプリケーションが示すものと、対応するすべてのエンジンで同じです。

## サブセットが含まないもの

このゲストが実装するのは、ひとつのエリア、ポイントツーポイントの隣接、シーケンス番号と確認応答つきのルーター LSA、Dijkstra です。それ以外は近似せずに拒否し、拒否は診断ログと「状態」の 1 行になります。`area` が 0 でないルーターは何もせず、理由を言います。同じインターフェース上の 2 台めのルーターはポートごとに一度拒否されます。間隔の違う hello や別のエリアからの hello は、理由とともに無視されます。同梱シナリオ `ospf-outside` は最初のものを見せます。r2 はエリア 1 にいて拒否を記録し、r1 は誰もいない相手に hello を送り続けます。

## 二つ目のラボ：BGP

`bgp-lab` は二つ目の学習ラボ「BGP：ポリシーで選ばれる経路」で、一覧では OSPF のラボの下にあります。四つの自律システムの四つのルーター。r1 は r2 と r3 とセッションを持ち、どちらも r4 とセッションを持ち、r4 がひとつのプレフィックスを発信します。セッションはリンク上で三段階で立ち上がり、保持時間のもとで keepalive により保たれます。インスペクターとタイムラインのピアのレポートがその状態を示します。r1 は間に自律システムをひとつ挟む二つの経路を持ち、長さではなく、r2 へのポートのパラメータであるローカルプリファレンスで選びます。ティック 1,000 でリンク r1-r2 が切れ、両端はただちにセッションを落とします。r1 はそこで学んだ経路を取り下げ、AS 3 を通る経路を選びます。2,000 でリンクが戻り、ローカルプリファレンスが最初の経路を呼び戻します。ラボの説明に試すことが書かれています。r2 をダウンさせて、最後のフレームから 90 ティック後に r1 の保持タイマーが切れるのを見る。ローカルプリファレンスを等しくして、決着が r4 が各隣接向けに設定した MED に、さらに低いルーター ID に移るのを見る。サブセット、その拒否、そのフレームは RFC 011 にあります。`bgp-outside` はひとつの自律システムの二つのルーターをリンクに置き、どちらも理由を記録して拒否します。

## 他の同梱シナリオ

| シナリオ | 見どころ |
|---|---|
| `dv-triangle` | 距離ベクトルのルーター 3 台が、スプリットホライズンで 100 ティックごとに広告します。r1-r2 のリンクが 1,000 で切れ、2,000 で直り、経路は r3 を通って、そして元へ、3 周期以内に収束し直します。 |
| `dv-chain` | 一列に並んだ距離ベクトルのルーター 4 台、`infinity = 3`。両端は互いの経路を決して持たず、地平線の向こうの経路は広告されません。 |
| `net-delay` | 1,500 バイトのフレームが 1000 Gbit/s、20 ns のリンクを渡り、送信の 32 ティック後に届き、エコーはその 32 後に届きます。遅延とシリアライズです。 |
| `net-loss` | `loss = 0.1` で 1 万フレーム、リンク自身のストリームから引きます。900 から 1,100 が失われ、どのエンジンでも同じフレームです。 |
| `net-jitter` | すべての到着が `[delay, delay + jitter]` の中に入ります。 |
| `net-link-down` | リンクが 300 でダウンし 600 でアップします。両端で `on-link`、飛行中のフレームは届き、ダウン中の送信は落とされます。 |
| `net-lan` | 3 台の LAN。フレームは他の 2 台に届き、それぞれが自分の損失の引きをします。 |
| `net-blackhole` | 組み込みの `network/blackhole` がすべてのフレームを落として数を報告します。計量なしです。 |

それぞれに「学習ラボ」の両言語の説明があり、`scenarios/digests.toml` に記録されたダイジェストがあって、適合キットがネイティブと Chromium、Firefox、WebKit で確かめます。
